# المنيب جو (almoneib-go)

ده موقع خدمة التوصيل بتاعتي في المنيب. في النسخة الجديدة (v2) غيّرت الفكرة من أساسها: مفيش حسابات عملاء خالص ولا ديون ولا خصومات ولا عروض. العميل يدخل، يكتب طلبه واسمه ورقمه وعنوانه (واللوكيشن لو حب)، ويبعت.

الستاك: Next.js 15 + Supabase + Cloudinary + Vercel.

## الطلب بيمشي إزاي
**العميل:** يكتب أصنافه وبياناته ويبعت، وبيتحوّل لصفحة متابعة برابط خاص بيه (`/order/<token>`). يقدر يلغي قبل ما حد يستلم الطلب، ويقيّم ويقدّم شكوى بعد التسليم.

**عندنا (مندوب / أدمن / سوبر أدمن، نفس الخطوات للكل):**
1. الطلب يظهر عند الكل، وأول واحد يضغط «استلام الطلب» يكمله والباقي يشوفه اختفى.
2. يبعت للعميل رسالة المتابعة على واتساب (إجباري قبل الأسعار).
3. يسجّل السعر الفعلي لكل صنف، ويضغط «في الطريق».
4. «تم التسليم» ← الفاتورة تتعمل لوحدها وتتبعت للعميل.

لو حد استلم طلب بالغلط فيه زرار «رجّع للكل». والإلغاء بيكون من الأدمن أو السوبر أدمن بسبب.

## الفاتورة
بتتعمل صورة في متصفح الموظف، وبتترفع على Cloudinary، ومتخزنة في `/admin/invoices` وأقدر أدوّر عليها برقم العميل وأبعتها تاني. الإرسال على واتساب يدوي (قائمة المشاركة على الموبايل، أو فتح شات العميل برابط الفاتورة)، مفيش WhatsApp API مدفوع.

## التشغيل
1. أنشئ مشروع Supabase جديد وشغّل `supabase/schema.sql` ثم `supabase/seed.sql` في SQL Editor.
2. من Authentication ← Providers ← Email: فعّل الإيميل والباسورد، وقفّل **Allow new users to sign up**.
3. انسخ `.env.example` لـ `.env.local` واملأه (Supabase، Cloudinary، VAPID، `NEXT_PUBLIC_SITE_URL`).
4. `npm install` ثم `npm run dev`.

### أول سوبر أدمن (مرة واحدة)
مفيش صفحة تسجيل. من Authentication ← Users ← Add user: البريد `01xxxxxxxxx@otlobha.local` + باسورد (Auto Confirm)، وبعدين في SQL Editor:
```sql
insert into public.users (id, phone, full_name, role)
select id, '01xxxxxxxxx', 'اسمك', 'super_admin'
from auth.users where email = '01xxxxxxxxx@otlobha.local';
```
وبعدها كل الموظفين من `/super/users`.

### إشعارات الإداريين
`supabase secrets set SEND_PUSH_WEBHOOK_SECRET=<سر>` و`supabase functions deploy send-push`، وبعدين Database Webhook على `notification_log` (INSERT) للدالة `send-push` بـ Header اسمه `x-webhook-secret`.

## الصلاحيات
- **مندوب:** الطلبات الجديدة وطلباته فقط.
- **أدمن:** كل الطلبات + الإلغاء + المنتجات والعملاء والفواتير والشكاوى والفريق.
- **سوبر أدمن:** كل ده + الإعدادات والتصنيفات والتقارير والعمولة والمستخدمين وسجل المراجعة والجلسات.

## الحماية من الطلبات الوهمية
حد للطلبات الجارية (3) وحد يومي (10) لكل رقم موبايل وجهاز، وعلى الـ IP بحد أوسع، وبيتعدّل من الإعدادات. بيتطبّق جوه الداتابيز في `create_guest_order`.
